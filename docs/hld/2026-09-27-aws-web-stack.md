# AWS web stack

Supersedes [docs/hld/2026-09-27-gcp-web-stack.md](2026-09-27-gcp-web-stack.md) (the GCP HLD) after
the user switched clouds on 2026-09-27. Every decision below marked *carried over* was made for GCP,
is cloud-neutral, and is cited to the section of the GCP HLD that holds its reasoning and evidence.
Nothing AWS-specific is carried over; each AWS fact below was checked against `../fakeaws`,
`policies/aws/`, `pitfalls/aws.yaml`, `prompts/aws/` and the provider documentation.

## Problem

The concept is proven on Scaleway: `web-live-paris` applies to a real account, serves HTTP, and a
holdout finds SSH closed (ADR-0033, ADR-0034; run `20260927T171147Z`). The user wants the same on
AWS, growing a more complicated stack over time, starting with a single webserver.

Today no such claim can be made about AWS. Everything that turns "the apply passed" into "the
server serves and nothing else is open" runs only under `sandbox_deploy`, and `sandbox_deploy` is
real Scaleway by construction (GCP HLD § Current state, unchanged). An AWS webserver can be
generated and mock-applied against fakeaws, but never observed running and never checked for what
it must not expose. On AWS the generator has already shown the failure the holdout exists for: the
last `aws-instance` run (`.infrafactory/runs/aws-instance/20260607T064123Z/generated/network.tf`)
opened SSH to the VPC range, and nothing would have noticed had it been `0.0.0.0/0`.

## Goals

*Carried over* from GCP HLD § Goals, decisions of 2026-09-27, with AWS names.

1. **The bar is `web-live-paris`, on real AWS.** A single webserver, generated by infrafactory,
   applies to a real AWS scope and serves HTTP through a public entry point, verified by
   `http_probe` against the running stack, and what answers is proven to be the pinned `service:`
   image (GCP HLD Goal 1, review F7/R2; the AWS mechanism is Design § Step one).
2. **A negative holdout runs against the real stack** and proves 22 and 443 are closed from the
   public internet, 443 as the positive control (ADR-0033, ADR-0034). "Every unrequested port" is
   the structural policy's job at Layer 1 (GCP HLD Goal 2, review F8).
3. **Real-cloud AWS is in scope**: an AWS Layer 3 with the fail-closed guarantees ADR-0023 gives
   Scaleway. Layer 2 alone cannot prove goals 1 or 2.
4. **The first step is the floor of a stack that grows.**
5. **An AWS Layer 3 failure feeds the repair loop and pitfalls, exactly as Scaleway's does**
   (GCP HLD Goal 5 and Design § A real failure is the next iteration's feedback, with the run
   evidence). Two exceptions: a holdout failure ends the run without repair (ADR-0033 § 5), and a
   failed sweep ends the run because the next iteration would apply onto the leak (review R3).

## Non-goals

*Carried over* from GCP HLD § Non-goals: the live path (`deploy`, TTL, reap, upgrade); the load
balancer in step one; Layer 3 for GCP or Genesys (GCP is paused, not resumed here); any
account-creating or account-closing operation; changing what Layer 3 means on Scaleway; scheduled
or CI-driven Layer 3 runs; replacing fakeaws; moving the AWS provider off `~> 5.70` in this HLD.

## Design

Decisions marked *carried over* stand as made for GCP; their reasoning is in the cited GCP HLD
section and is not repeated. AWS-specific decisions are marked with the user and the date.

### Containment: a clean, dedicated scope with whole-scope ownership

*Carried over* (GCP HLD § Containment unit, § Inside the project; user decisions Q2, Q3, R3):

- One dedicated scope holding nothing else, set up once by hand and stamped; the run never
  creates or deletes the scope. Least privilege decided it over scope-per-run.
- Whole-scope ownership: `no_orphans` means the scope is empty, and "empty" is enumerated over a
  fixed list of collections independent of the allowlist; a 403 or partial page fails the sweep.
- **The collection list is written here, not left to a story** (review H3). In the pinned
  region: instances (a leak unless `terminated`), volumes, network interfaces, Elastic IPs,
  security groups other than a VPC's default, VPCs, subnets, internet gateways, route tables other
  than a VPC's main, NAT gateways, key pairs, owned snapshots and images, launch templates; for
  step two, load balancers, target groups and listeners; and SSM parameters outside the fixed
  prefix. A settle loop retries for a bounded window while anything is `shutting-down`,
  `deleting` or `detaching`, then fails closed. Pagination is completed or the sweep fails. A test
  asserts that every allowlisted type maps to a swept collection and every swept collection has a
  `reap` delete, in dependency order. "Empty" is not literal on AWS: a terminated instance stays
  listed for about an hour, so the instance filter is part of the definition. The default-VPC
  assertion is one row of this list, not a substitute for it.
- Serial runs. A claim is taken before anything touches the cloud, fails closed naming the
  holder, is released only when the sweep proves the scope empty, is taken over by `reap`, and is
  not re-entrant: a failed sweep ends the run.
- Tags report, never gate. The run id reaches every taggable step-one type through
  `default_tags` in the provider block infrafactory writes, so the model never writes it (review
  L3; `aws_route` and `aws_route_table_association` are not taggable). `reap` has a state-free path
  gated by scope id, stamp and claim.
- **The claim and the stamp are two SSM Parameter Store parameters under a fixed prefix** (user,
  2026-09-27). `PutParameter` with overwrite disabled fails if the name exists, a real
  compare-and-swap at creation; the claim's value is the holder's run id, deleting it releases it,
  and the stamp is a second parameter that preflight and `reap` read. Standard-tier parameters are
  free, regional and account-scoped; the sweep treats the prefix as infrastructure. The IAM user
  gains only `ssm:PutParameter`, `ssm:GetParameter` and `ssm:DeleteParameter` scoped to that
  prefix. An EC2 key pair as a lock (no extra IAM, but a credential object used as a lock inside
  the collection the sweep enumerates) and a DynamoDB or S3 conditional write (a resource and a
  service the credential would otherwise not need) were rejected.

**The scope is a dedicated member account under AWS Organizations, holding nothing else**
(user, 2026-09-27). The user creates it clean. The account boundary is the scope: the credential
lives inside it and holds nothing above it, the sweep enumerates that account's EC2 collections in
the pinned region, and any stray is a leak by definition. A region inside an existing account was
rejected because the scope would be a convention, not a boundary; walking every region was rejected
as a per-iteration cost for a stack pinned to one region. The region pin is therefore made a
boundary, not a convention (review M3), in three places: the gate requires exactly one
`provider "aws"` block with no `alias`, no `provider =` meta-argument on any resource, and `region`
equal to the configured region (the Scaleway provider check, `layer3_hcl_shape.go:87-97`, refuses
`api_url` and `project_id` but not a second block); the IAM user's policy carries an
`aws:RequestedRegion` condition; and a Service Control Policy on the member account denies every
action outside the pinned region and every service but EC2, SSM and STS, enforced by AWS whatever
the user's policy says. The SCP is applied at setup and recorded in `docs/operations.md`;
preflight cannot assert it from inside the account, and says so. The default VPC in the pinned region is
deleted at setup and preflight asserts it is gone, so "empty" needs no allow-list of default
resources (Risks).

### Step one: an instance with a public IP; the load balancer second

*Carried over* (GCP HLD § Step one, user decision Q4). Step one is `aws_vpc`, `aws_subnet`,
`aws_internet_gateway`, `aws_route_table` with a default route, `aws_route_table_association`,
one `aws_security_group` admitting 80 from the internet, and one `aws_instance` with a public
address. The load balancer is step two. Both `http_probe` and the holdout dial the instance's
public address.

Two things must change in infrafactory (GCP HLD review F4, F19, transferred and verified above):
`deriveTopologyAWS` must derive `compute:<port>` from a mock instance with a public address and an
ingress rule admitting that port from a public source, and `aws_eip` is admitted, at most one
block (review L2: with `count` refused, addresses are instances plus EIP blocks, and an
unassociated EIP bills), because models reach for a static address when asked for a public entry
point.

**Layer 2 for this stack runs on fakeaws** (user, 2026-09-27: "we own the mock"; closes review H1
and H2). The moto assessment (`.swarm/research/moto.md`) is kept as a reference oracle: where it
shows what a mature mock returns (an instance's `groupSet` taken from the primary network
interface, `moto.md:314-334`; the exact validation error codes, § 3.6) that is evidence of what
real AWS returns, and where the AWS documentation says otherwise the documentation wins. The
fakeaws work the stack needs is written here as preconditions, ordered by which step needs them
first, so that step one needs the fewest:

**Step one needs, in this order** (all reproduced against fakeaws `069d705` with the `~> 5.70`
provider, `.swarm/moto/`; the list is the report's fix-fakeaws list, `moto.md:40-51`):

1. **STS `GetCallerIdentity`** (H2). Without `skip_credentials_validation` and
   `skip_requesting_account_id` the provider calls it at init and fakeaws answers 501
   (`moto.md:246`), so the layer-neutral configuration cannot start. One Query-protocol action
   returning the fake account id, user id and ARN; then all three `skip_*` flags leave the HCL, the
   account id is looked up as on real AWS, and the ADR-0023 rule 3 ARN check stays literal instead
   of meeting client-built ARNs with an empty account (Current state).
2. **`RunInstances` accepts the `NetworkInterface.N.*` shape**: subnet, security groups and
   `AssociatePublicIpAddress` under the network interface, no top-level `SubnetId`. This is what
   the provider sends whenever `associate_public_ip_address = true`, the shape this HLD chose, and
   fakeaws answers 409 today (`ec2.go:1417-1424`). The instance's groups are reported at instance
   level from its primary interface, as real AWS does; moto's failure to do so is the one bug the
   assessment found on this path, so it is written as a test here, not inherited.
3. **The subnet persists and echoes `MapPublicIpOnLaunch`** instead of a no-op 200
   (`ec2.go:64-70`), so the provider's poll completes and the learned pitfall against the
   attribute is retired by the pipeline, never by hand (Risks).
4. **The instance carries `ipAddress` and `privateIpAddress`** in `DescribeInstances`
   (`ec2InstanceXML`, `ec2.go:1307`), so `aws_instance.public_ip` is real in state and the
   topology derivation has an address to read.
5. **`UserData` is persisted by `RunInstances` and returned base64 by
   `DescribeInstanceAttribute`** (`ec2.go:1888-1889` returns `""`), so the provider's state hash
   matches on the second plan and ADR-0032's drift stop does not end every iteration.
6. **`/mock/state` exports `ip_permissions` per security group and the instance IPs**
   (`gatherEC2StateReal`, `ec2.go:2018-2030` carries neither), so the structural policy's
   `deny_state` half and `deriveTopologyAWS` have input.
7. **SSM Parameter Store**: `PutParameter` with `Overwrite=false` failing `ParameterAlreadyExists`
   on a second call, `GetParameter`, `DeleteParameter`, and the AL2023 public parameter resolving
   to an AMI the EC2 fixtures know. fakeaws has no SSM today; the claim, stamp and AMI resolver
   need exactly these (moto's behaviour at `moto.md:295-306` is the oracle for the shapes).
8. **Ingress validation**: CIDRs parsed, ports within 1 to 65535 and ordered, protocols known,
   with AWS's error codes (`InvalidParameterValue`, `InvalidPermission.Malformed`), so a rule real
   AWS rejects does not pass the mock and cost a real iteration. Ordered last because steps 1 to 7
   make the stack apply; this makes the mock refuse what it should.

**Step two needs**: `securityGroupRuleSet` with rule ids on `Authorize*` (or the allowlist refuses
`aws_vpc_security_group_*_rule` and the prompt says which shape to write; today the provider
crashes, `apply-web-fakeaws-false.log:186`), and an **ELBv2** service (load balancers, target
groups, listeners, `Describe*` into `/mock/state`), which fakeaws does not have at all.

Each surface ships with its validation errors, not only its happy path (Risks), is tested against
`~> 5.70`, and moves into `coverage_matrix.yaml` and the cross-repo parity test in the same slice.

**The webserver is a container on Amazon Linux 2023, started by `user_data` that infrafactory
renders and the model never writes** (user, 2026-09-27). infrafactory renders one fixed script
from `service:`: install docker, run the pinned `image:tag` on the declared port. How the script
enters the configuration (review M1): infrafactory writes it to `infrafactory-user-data.sh` in the
generated directory, and the model must write exactly
`user_data = file("${path.module}/infrafactory-user-data.sh")`, one exact expression the gate
already knows how to enforce (`layer3_hcl_shape.go:701-720` does it for `project_id`). The gate
requires exactly one `aws_instance`, that expression for `user_data`, `ami` equal to the id
resolved this run, `user_data_base64` and `user_data_replace_on_change` absent, and
`aws_launch_template` not admitted, so no other path starts a server (S156d: new paths inherit
unwritten rules). After apply, the instance's user data read from the API
(`DescribeInstanceAttribute userData`, base64) must equal the rendered file byte for byte; the
state's `user_data` is a SHA1 and is not what is compared. `http_probe` reachable then proves that
image is what answers. This is the GCP R2 closure by construction: AWS
has no standalone Container-Optimized OS equivalent (Bottlerocket needs ECS or EKS) where a
declaration is the only thing that starts a server, so the declaration is made by infrafactory
instead (review L5). The ECS-optimized AMI (docker
preinstalled, shorter boot) was rejected because its agent fails on every boot without a cluster;
model-written `user_data` was rejected because what runs would be free text and the only version
proof an HTTP body nginx never names. The probe window is re-measured for a docker install on
AL2023; the Scaleway figure was sized to the same install on a different cloud and is the starting
guess, not evidence.

**An ephemeral public address, and an AMI id infrafactory resolves once per run** (user,
2026-09-27). The instance sets `associate_public_ip_address = true` on a subnet in the run's VPC;
no extra resource, and the probe already reads `aws_instance.public_ip`. `aws_eip` stays admitted
so a model that reaches for one is not refused an iteration, but nothing requires it. For the
image, infrafactory reads the Amazon Linux 2023 public SSM parameter once per run and hands the
literal id to the model, and the gate requires the model to have used it (review M1: the
2026-06-07 run wrote `ami-0c55b159cbfafe1f0` from memory, an id that on real AWS is gone or a
Marketplace image with an hourly fee). The phase-1 rule against `data` sources stands and the id
never rots. When Layer 3 is disabled the id is the mock's fixture (`ami-0abcd1234`, `ec2.go:1769`);
when it is enabled the resolver runs inside the sealed environment after `sts:GetCallerIdentity`
and before generation, and a parameter that cannot be read fails the run before anything is
generated (review M2). The credential gains `ssm:GetParameter` on that public path. A
literal id pinned in the prompt was rejected because it is region-specific and deprecated over
time, and when it rots every real iteration fails and the pipeline learns a pitfall that is not one.

### The gate: one gate parameterised by cloud

*Carried over* (GCP HLD § Step one, review F6, R1; user decisions): cloud-neutral rules unchanged
(pure-function allowlist, no `provisioner`, `connection`, `module` or `data "external"`, pinned
provider source exactly `hashicorp/aws`, index-without-`try` refusal, `count` and `for_each`
refused outright as the Scaleway gate refuses them). Cloud-specific rules bound cost and
destroyability, agreed 2026-09-27: `instance_type` is `t3.micro` or `t3.small`; the root volume
is at most 20 GB `gp3`; no additional EBS volumes; `disable_api_termination` absent or false and
`root_block_device.delete_on_termination` absent or true, the two AWS shapes that survive
`tofu destroy`. `t3.small` is admitted so a model that judges nginx needs more than a micro is not
refused an iteration. At list prices a `t3.micro` is about $0.010 per hour, the public IPv4 about
$0.005 and a 20 GB `gp3` about $0.002, so five iterations of five minutes is about one cent, and
with `count` refused and `aws_eip` bounded to one block the address count is at most two (L2).

### Identity and the sealed environment

*Carried over* (GCP HLD § Identity, user decision Q5, reviews F1, F2, R4, R5, F21):

- A dedicated least-privilege credential in a mode 0600 file beside `layer3.env`; never the
  account owner's login. The instance runs with no instance profile.
- The generated configuration is layer-neutral; the layer lives in the environment. Everything
  `buildAwsProviderBlock` bakes in moves out of the HCL: Layer 2's `cloudEnv` sets
  `AWS_ENDPOINT_URL_<SERVICE>` for every service fakeaws serves plus the fake keys it already
  sets; Layer 3's sealed environment strips all of them and sets the credential and region. The
  generated block becomes `provider "aws" { region = ..., s3_use_path_style = true }`: path style
  has no environment form, real S3 serves it, and SeaweedFS needs it, so it is layer-neutral and
  stays (review H2; recorded as the exception in the layer-neutral-configuration ADR). The gate
  refuses `endpoints`, `access_key`, `secret_key`, `token`, `profile`, `shared_config_files`,
  `shared_credentials_files`, `assume_role*` and the `skip_*` flags in HCL.
- **fakeaws's STS `GetCallerIdentity` answers review H2** (Design § Step one, item 1). Layer 2
  points `AWS_ENDPOINT_URL_STS` at fakeaws, all three `skip_*` flags leave the HCL, the account id
  is looked up as on real AWS, and the ADR-0023 rule 3 ARN check stays literal.
- The third leg of ADR-0023 rule 2 is a file on disk: the AWS SDK falls through to
  `~/.aws/credentials` and `~/.aws/config`, whose `services` section can redirect endpoints, and to
  the instance metadata service on any EC2 development box. The strip is a prefix, not an
  enumeration (review M5; `SandboxStripEnv` already takes prefixes, `sandbox_deploy.go:43-44`):
  strip `AWS_*`, then set exactly `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`,
  `AWS_EC2_METADATA_DISABLED=true`, and `AWS_SHARED_CREDENTIALS_FILE` and `AWS_CONFIG_FILE` to
  paths that do not exist; keep the `HTTP_PROXY`, `HTTPS_PROXY`, `SSL_CERT_FILE`, `TF_VAR_*` and
  `TF_CLI_ARGS*` entries. One environment builder serves tofu and infrafactory's own SDK calls
  (preflight, the AMI resolver, the sweep, `reap`). The builder refuses without the credential
  file, and preflight calls `sts:GetCallerIdentity` and requires the account and principal it
  expects.
- After apply, every resource in `terraform-live.tfstate` that has an ARN or `owner_id` must carry
  the expected account id; a child type with neither (`aws_route`, `aws_route_table_association`)
  is checked through its parent, the `layer3ChildScopedTypes` shape, and a type with neither and
  not on that list is refused (review L1).

**The credential is an IAM user inside the dedicated account with a long-lived access key**
(user, 2026-09-27). The user holds only the EC2 actions step one needs, in the pinned region,
nothing outside the account; the key lives in the mode 0600 file and preflight verifies the
account and principal with `sts:GetCallerIdentity` before anything is applied. The account
boundary already bounds the key's reach. A role assumed through STS from the operator's identity,
with temporary keys written to the same file outside the seal, is the first upgrade once rotation
is the concern; not chosen now because a `reap` hours later needs a fresh session and a wrong trust
policy makes the run act as whoever assumed it.

### Step one is `run` and `test`

*Carried over* (GCP HLD § Step one is `run` and `test`, user decision Q6). Done when a generated
`aws-web-live` reaches its target on real AWS with what serves proven to be the pinned image, the
holdout finds 22 and 443 blocked, and the sweep finds the scope empty. `--keep` and `deploy` are
refused for AWS until the live path lands.

### A real failure is the next iteration's feedback; a holdout failure is the end

*Carried over* in full (GCP HLD § A real failure is the next iteration's feedback, with the
Scaleway run evidence and code citations). AWS failures land in `pitfalls/aws.yaml` through the
same extractors; a run ending `repair_budget_exhausted` or `stuck` without a learned entry is a
pipeline bug.

### The prohibition is written down before the holdout checks it

*Carried over* in principle (GCP HLD § The prohibition, ADR-0034, review F10). On AWS a security
group denies ingress by default; the openings are `ingress` blocks, `aws_security_group_rule`
and `aws_vpc_security_group_ingress_rule` (review M4). The structural policy in `policies/aws/`
walks all three shapes, or the allowlist admits exactly one and the prompt says which; a policy
that walks two fails open on the third. "Public source" covers `cidr_blocks`, `ipv6_cidr_blocks`
(`::/0` is public), `cidr_ipv4` and `cidr_ipv6`, including two-halves shapes; `prefix_list_ids`
are opaque and refused; `security_groups`, `self` and `referenced_security_group_id` are not
public. No public-source rule may admit 22, use protocol `-1`, or span `from_port = 0,
to_port = 0`, the AWS spellings of "everything"; the instance has no instance profile. It runs
against every AWS plan and is named as a criterion so its state half runs at Layer 2, which needs
the mock to export `ip_permissions` (Design § Step one): today `/mock/state` carries no rules, so
the state half would pass vacuously, the undefined-is-not-false defect
the policy-correctness epic (done) records for the existing AWS
policies. That epic's Rego-test requirement applies to this policy on day one, and its record that
`deny_state` never runs against real state stands: the holdout is the only real-state check.

## Alternatives

- **Resume GCP.** Not this HLD; the GCP HLD is kept, superseded, for when it is.
- **Stay at Layer 2 for AWS.** Rejected for the reason given for GCP (GCP HLD § Alternatives).
- **Scope per run (an account per run).** Rejected before being asked: AWS account creation is
  slow, closing one takes 90 days, and it needs Organizations-level rights, the opposite of least
  privilege. The GCP reasoning against project-per-run applies with more force.
- **Tag-gated sweep.** Rejected (GCP HLD § Inside the project): fails open on an untagged stray.
- **Adopt moto for EC2/VPC, ELBv2, IAM, STS and SSM, the way SeaweedFS replaced S3.** Rejected by
  the user: we own the mock. The evidence stands in one line: step one applied on moto and could
  not start on fakeaws, and the 17-resource ALB stack passed on moto where fakeaws has no ELBv2
  (`.swarm/research/moto.md` § Recommendation). moto stays a reference oracle for what real AWS
  returns; the AWS documentation wins where they differ.

## Risks and safety

**Real money, third cloud's guards.** Every ADR-0023 rule gets an AWS implementation, each
fail-closed, as listed for GCP (GCP HLD § Risks). ADR-0025 is not carried over.

**A mock-learned pitfall is right about the mock and wrong about the cloud.** `pitfalls/aws.yaml`
forbids `map_public_ip_on_launch` because fakeaws's no-op `ModifySubnetAttribute` makes the
provider time out (Current state, review H1): the no-op is the failure, not the fix. The rule is
correct until the mock accepts the attribute and wrong about real AWS throughout. Sweep protocol
says fix forward at the source and let the pipeline retire the rule; never hand-edit the pitfall.

**The fakeaws effort is real and found reactively.** The assessment prices each new fakeaws
surface at one to two hours per service, discovered when a run hits it (`moto.md:40-51`,
`../fakeaws/AGENTS.md:138`); step one needs eight surfaces before the stack applies (Design § Step
one), and today none of the four web-stack variants applies against fakeaws at all
(`moto.md:161-183`). This is the cost the user accepted for owning the mock, and it sits on the
critical path of Rollout step 2.

**A permissive mock certifies wrong fixes.** A surface that accepts everything passes the happy
path and lets a rule real AWS rejects reach a real apply, at the price of a real iteration; worse,
a repair the loop makes against the permissive mock can be a wrong fix the mock certified. So each
new fakeaws surface ships with its validation errors, not only its happy path: the exact AWS error
codes for malformed CIDRs, inverted ports, unknown protocols, a duplicate SSM parameter, a
`RunInstances` with both a top-level `SubnetId` and a network interface. moto's codes (§ 3.6, 15
of 26 exact) are the oracle for what to return; the AWS API reference wins where they differ.

**AMI rot.** Closed by resolving the id per run (Design § Step one); the residual risk is the
resolver itself, which fails closed if the parameter cannot be read.

**Default resources are not empty.** Every AWS region has a default VPC with a default security
group that cannot be deleted while the VPC exists. Setup deletes the default VPC in the pinned
region and preflight asserts it is gone, so the sweep's "empty" is literal.

**Public IPv4 is billed** since 2024-02-01, ephemeral or EIP; with `count` refused and `aws_eip`
bounded to one block the address count is at most two, and the sweep lists addresses (L2).

**ADRs touched.** ADR-0023 (third implementation), ADR-0014 (its endpoint-flag discipline was
written for GCP; the AWS analog is new), ADR-0033 and ADR-0034 (third cloud), ADR-0013 (Proposed;
now reached by two clouds' Layer 3 plans). New ADRs: whole-scope ownership for AWS, and the
layer-neutral provider configuration.

## Rollout

*Carried over* in shape (GCP HLD § Rollout, reviews F14, R7):

1. **The empty scope, guarded.** Member account created clean, default VPC deleted, SCP applied,
   IAM user and SSM stamp created, all by hand and recorded in `docs/operations.md`; the sealed
   environment and credential preflight first; then the claim, the enumerated sweep with its
   settle loop, and `reap`. Done when a planted leak makes the sweep fail naming it and `reap`
   removes it, and a second run is refused with the holder's id. The planted leak is a detached
   network interface or an unassociated Elastic IP, the two things the mock never models, not an
   instance (review H3). No generated HCL yet.
2. **Step one.** First the fakeaws work in Design § Step one, items 1 to 8, each with its
   validation errors and its `coverage_matrix.yaml` row; then the layer-neutral provider
   configuration with `AWS_ENDPOINT_URL_STS` and the AWS topology derivation;
   then the AWS allowlist and gate (including the region, `user_data`, AMI and EIP rules), the
   ingress policy with its Rego tests, the `aws-web-live` scenario and its holdout. Done per
   Design § Step one is `run` and `test`.
3. **Step two: the load balancer**, with fakeaws's ELBv2 service and `securityGroupRuleSet`
   first (Design § Step one, "Step two needs"), then the probe window re-measured.
