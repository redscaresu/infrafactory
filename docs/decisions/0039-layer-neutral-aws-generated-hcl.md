# ADR-0039: Layer-Neutral AWS Generated HCL

## Status
Accepted

## Context

AWS is infrafactory's third cloud, after Scaleway and GCP. Both earlier clouds ended up with a
provider block and an environment that differ between Layer 2 (fakeaws) and Layer 3 (real
account), and with tests that assert cloud-parity properties as an afterthought rather than a
starting contract. `aws-layer-neutral-hcl` (`docs/epics/aws-layer-neutral-hcl.md`) exists to not
repeat that: the generated bytes for a given model output are identical across layers, and the
routing between layers lives entirely in environment variables and CLI wiring, never in the HCL
the model wrote or infrafactory rendered.

This ADR is the layer-neutral analog of ADR-0014 (which did the same job for the v5 GCP
provider): it records what the AWS provider actually reads, and the decisions that keep that
surface identical whether the target is fakeaws or a real AWS account.

## Decision

1. **cloudEnv is Layer 2's complete AWS environment.** `internal/cli/test_command.go`'s cloudEnv
   sets `AWS_ENDPOINT_URL_<SERVICE>` for all 12 services the AWS provider reads endpoints for
   (EC2, IAM, EKS, RDS, SQS, DYNAMODB, SECRETS_MANAGER, KMS, ROUTE_53, S3, STS, SSM), plus a
   catch-all `AWS_ENDPOINT_URL` pointed at a dead loopback address, plus `AWS_CONFIG_FILE` and
   `AWS_SHARED_CREDENTIALS_FILE` pointed at paths that do not exist. When `fakeaws.url` is empty,
   every one of those endpoint variables resolves to the dead loopback constant rather than being
   omitted, so a service the wiring forgot to route fails closed at the catch-all instead of
   escaping to real AWS.

2. **Every Layer 2 tofu command strips inherited `AWS_*`.** `harness.Layer2StripEnv` removes the
   `AWS_*` family from the parent process's environment on every Command the static, mock-deploy
   and destroy harnesses build. cloudEnv is additive on top of that strip, so a shell-exported
   `AWS_PROFILE` or `AWS_ACCESS_KEY_ID` in the invoking session can never reach tofu.

3. **The provider block is exactly `region` and `s3_use_path_style`.** No `access_key`,
   `secret_key`, `skip_*`, `endpoints` block or alias. `s3_use_path_style` is the one provider
   attribute with no environment form — the AWS SDK has no `AWS_S3_USE_PATH_STYLE` equivalent — so
   it is the sole exception to "route by environment, not by HCL". `region` comes from one
   `awsRegion(cfg)` helper called identically at both layers, so a region typo cannot diverge
   between them.

4. **`required_providers` pins exactly `5.100.0` at both layers**, overriding whatever version the
   model wrote. Layer-neutral means byte-identical generated files with Layer 3 enabled and
   disabled; a version the model is free to choose would be the first byte to diverge.

5. **Without `skip_*`, AWS Layer 1 and `validate` need fakeaws STS up.** Removing
   `skip_credentials_validation` / `skip_requesting_account_id` (ADR-0014's GCP analog never had
   this problem; AWS's provider calls `GetCallerIdentity` at configure time) means `validate` now
   depends on a live STS endpoint. `AWS_ENDPOINT_URL_STS` must resolve to fakeaws, and fakeaws's
   STS handler must be reachable, before `validate` — not just `apply` — can succeed.

6. **infrafactory renders `infrafactory-user-data.sh`; the model never writes one.** For an AWS
   scenario carrying a `service:` block, infrafactory renders the install-and-run script from
   `ServiceSpec` and refuses model-generated HCL that supplies its own file at that path. The
   model's only contract is the literal line
   `user_data = file("${path.module}/infrafactory-user-data.sh")`.

7. **Layer 2 uses the AMI fixture `ami-0al2023x8664`; Layer 3 reads SSM through the sealed SDK
   construction.** `internal/harness/aws_client.go:28-52`'s pattern (static credentials from the
   sealed env map, an explicit `BaseEndpoint`, never `config.LoadDefaultConfig`) is reused for the
   SSM client that resolves the real AL2023 AMI id at Layer 3. The default credential chain is
   never used in production code, at either layer — an audited invariant, not a convention.

8. **The AWS size table is literal in `prompts/aws`.** `mappings.yaml` is read by no code path
   today (`ResolvedMappings` renders empty for every cloud); rather than wire a mechanism that has
   never been exercised, the AWS instance-size table is written directly into the phase-1 prompt.

9. **`default_tags` is deferred.** The epic's original plan put `default_tags` carrying the run id
   into the provider block so every AWS resource is taggable back to its run. fakeaws does not yet
   round-trip tags on six of the services a full-stack scenario can touch (sqs, iam, rds, route53,
   dynamodb, eks) — see the new `fakeaws-tags-every-service` story. A `default_tags` block added
   now would silently no-op against those services: nothing in the mock would fail, but the tag
   would not be there to sweep or reap by, and this ADR's layer-neutral guarantee is that
   generated bytes and behavior match at both layers, which a partially-effective tag cannot
   satisfy. `default_tags` lands only once `fakeaws-tags-every-service` closes; the blocked
   `aws-default-tags-run-id` story carries it.

   **Amendment (2026-09-28): resolved.** The provider block gains `default_tags { tags = {
   "infrafactory-run-id" = "<run id>" } }`, the id taken from the run, never the model; a bare
   `generate` has no run and writes none. Bytes stay identical across layers except that value.
   Model HCL that names the key is refused, since a resource's own tag overrides `default_tags`.
   fakeaws round-trips tags on every resource it converges, so the deferral's reason is gone
   (`aws-default-tags-run-id`'s PR carries the evidence).

This ADR is also the AWS analog of ADR-0014: it enumerates what the AWS provider actually reads,
the same way ADR-0014 enumerated it for the GCP v5 provider — environment (`AWS_ENDPOINT_URL_*`,
`AWS_ENDPOINT_URL`, `AWS_REGION`, `AWS_PROFILE`), the shared config file's `services` block
(neutralized here by pointing `AWS_CONFIG_FILE` at a nonexistent path, decision 1), and IMDS
(neutralized by never using the default credential chain, decision 7).

## Consequences

**Benefits**:
- A model output's generated files are byte-identical whether Layer 3 is enabled or not; only the
  region literal changes, and only because `aws.region` changed.
- Every AWS service the provider can route to is enumerated once, in cloudEnv, instead of
  discovered piecemeal per scenario when one falls through to a dead endpoint.
- The sealed-SDK-construction pattern from Layer 3's STS client generalizes directly to the AMI
  resolver's SSM client, so Layer 3 gains no second way of reaching AWS.

**Tradeoffs**:
- `validate`, not just `apply`, now has a live-STS dependency; a fakeaws outage now blocks a wider
  set of commands than it did before `skip_*` was removed.
- `default_tags` is out for this arc. Runs before `aws-default-tags-run-id` lands cannot be
  correlated back to their run by AWS resource tag; sweep and reap for AWS rely on other
  mechanisms (`aws-layer3-claim-sweep-reap`'s collection list) until then.
- `mappings.yaml` stays unread for AWS as it is for the other two clouds; a literal prompt table
  is one more place the size table can drift from the YAML if either is edited without the other.

**Follow-up work**:
- `aws-default-tags-run-id` (blocked on `fakeaws-tags-every-service`): add the `default_tags`
  block once every AWS service a scenario can touch round-trips tags.
- `fakeaws-tags-every-service` (repo fakeaws): round-trip tags on sqs, iam, rds, route53,
  dynamodb and eks, the six services blocking decision 9.
