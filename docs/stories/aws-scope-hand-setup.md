# The user builds the AWS scope by hand: a clean member account, its default VPC deleted, and an IAM user that may write only the claim, whose policy a test ties to the sweep and the reap. Then the 0600 key file, the stamp, and the SCP. Each step is verified

The lead writes the policy files and the runbook in docs/operations.md § Layer 3 (AWS) › Scope setup; the user runs it. Set REGION, ACCOUNT_ID and MGMT (the Organizations management profile) as shell variables first. The account id and key id never enter git, because the repo is public.
0. ~/.aws/config: [profile infrafactory-admin] role_arn=arn:aws:iam::ACCOUNT_ID:role/OrganizationAccountAccessRole source_profile=MGMT region=REGION.
1. Account: `aws organizations create-account --email <unused email> --account-name infrafactory-layer3 --profile $MGMT --query CreateAccountStatus.Id --output text`. Poll `aws organizations describe-create-account-status --create-account-request-id <id> --profile $MGMT --query 'CreateAccountStatus.[State,AccountId]' --output text` until it prints SUCCEEDED. Verify: describe-account shows Status ACTIVE, and `aws sts get-caller-identity --profile infrafactory-admin --query Account` prints ACCOUNT_ID.
2. Default VPC: `VPC=$(aws ec2 describe-vpcs --filters Name=isDefault,Values=true --query 'Vpcs[0].VpcId' --output text --profile infrafactory-admin --region $REGION)`. Delete every subnet in it (`aws ec2 describe-subnets --filters Name=vpc-id,Values=$VPC`, then `aws ec2 delete-subnet`). Get IGW from `describe-internet-gateways --filters Name=attachment.vpc-id,Values=$VPC`, then run detach-internet-gateway, delete-internet-gateway and `aws ec2 delete-vpc --vpc-id $VPC`. Verify: describe-vpcs, describe-subnets, describe-internet-gateways, describe-network-interfaces, describe-addresses and describe-instances are all empty in $REGION.
3. IAM user, before the SCP, since the SCP denies IAM: `aws iam create-user --user-name infrafactory-layer3 --profile infrafactory-admin`. Then `sed -e "s/REGION/$REGION/g" -e "s/ACCOUNT_ID/$ACCOUNT_ID/g" docs/layer3/aws/iam-policy.json > "$TMPDIR/p.json"` and `aws iam put-user-policy --user-name infrafactory-layer3 --policy-name infrafactory-layer3-scope --policy-document file://$TMPDIR/p.json --profile infrafactory-admin`. The policy covers claim, sweep and reap only; the apply actions are aws-web-live-on-real-aws's. It grants: sts:GetCallerIdentity; ssm:PutParameter and ssm:DeleteParameter on .../parameter/infrafactory/layer3/claim only; ssm:GetParameter on .../claim and .../stamp; ssm:DescribeParameters and ec2:Describe* on * with aws:RequestedRegion=REGION; and exactly the EC2 actions ReapAWSScope exports, with the same condition. Verify with `aws iam simulate-principal-policy --policy-source-arn arn:aws:iam::${ACCOUNT_ID}:user/infrafactory-layer3 --profile infrafactory-admin --query 'EvaluationResults[].EvalDecision'`: ssm:PutParameter on .../claim is allowed; ssm:PutParameter and ssm:DeleteParameter on .../stamp and on .../other are implicitDeny; ec2:DescribeVpcs with --context-entries ContextKeyName=aws:RequestedRegion,ContextKeyValues=us-east-1,ContextKeyType=string is implicitDeny; ec2:RunInstances is implicitDeny.
4. Key file, never printed: `mkdir -p ~/.config/infrafactory && (umask 077; aws iam create-access-key --user-name infrafactory-layer3 --profile infrafactory-admin --query 'AccessKey.[AccessKeyId,SecretAccessKey]' --output text | awk '{printf "AWS_ACCESS_KEY_ID=%s\nAWS_SECRET_ACCESS_KEY=%s\n",$1,$2}' > ~/.config/infrafactory/layer3-aws.env)`. This is aws_preflight.go:71's path. Verify: `stat -f %Lp` prints 600, and `cut -d= -f1` prints exactly the two names. Then `(set -a; . ~/.config/infrafactory/layer3-aws.env; set +a; env -u AWS_PROFILE AWS_CONFIG_FILE=/dev/null AWS_SHARED_CREDENTIALS_FILE=/dev/null aws sts get-caller-identity --region $REGION --query '[Account,Arn]' --output text)` prints ACCOUNT_ID and the user ARN. Those two values and REGION go into the local config's aws block (config.go:135-146).
5. Stamp, written by the admin because the key cannot: `aws ssm put-parameter --name /infrafactory/layer3/stamp --type String --value $ACCOUNT_ID --region $REGION --profile infrafactory-admin`. Verify: describe-parameters lists only the stamp, and its Value is ACCOUNT_ID.
6. SCP, last, from MGMT. If SCPs are not enabled, run enable-policy-type SERVICE_CONTROL_POLICY on the root. Then sed docs/layer3/aws/scp.json into $TMPDIR. It has two Deny statements: NotAction [ec2:*, ssm:*, sts:*], and * when aws:RequestedRegion!=REGION. Both are ArnNotLike aws:PrincipalArn arn:aws:iam::*:role/OrganizationAccountAccessRole, a recorded exemption so the admin can rotate the key and plant leaks. Create it with `POLICY=$(aws organizations create-policy --name infrafactory-layer3-scope --type SERVICE_CONTROL_POLICY --description 'infrafactory Layer 3 scope' --content file://$TMPDIR/scp.json --query Policy.PolicySummary.Id --output text --profile $MGMT)`, then `aws organizations attach-policy --policy-id $POLICY --target-id $ACCOUNT_ID --profile $MGMT`. Verify: list-policies-for-target names infrafactory-layer3-scope. With the key sourced, `aws s3api list-buckets` is denied with a message naming a service control policy, and `aws ec2 describe-vpcs --region us-east-1` is denied.

**Done when:**

- internal/harness/aws_scope_policy_test.go reads docs/layer3/aws/iam-policy.json. It fails if any mutating EC2 action the policy allows is neither in ReapAWSScope's exported action list nor mapped to a swept collection. It fails on any ec2 or ssm wildcard other than ec2:Describe*. It fails if ssm:PutParameter or ssm:DeleteParameter reaches beyond .../claim. It fails if an action ReapAWSScope sends is not allowed. It also reads docs/layer3/aws/scp.json and fails unless the allowed services are exactly ec2, ssm and sts, the region deny is present, and the only exemption is OrganizationAccountAccessRole.
