# policies/aws/default_deny_ingress.rego denies every public opening across four ingress shapes, at any module depth and with unknowns failing closed, and its state half runs at Layer 2

- Name: package aws.default_deny_ingress, criterion `default_deny_ingress`, the same name web-live-paris uses (web-live-paris.yaml:46). Add cloudConstraintPolicies["aws"]["default_deny_ingress"] (test_command.go:1530-1537). Without that entry, AWS falls back to the flat map's Scaleway policy (infrafactory.yaml:252), which passes vacuously (test_command.go:1576-1587).
- Walk input.resource_changes (mode managed, action not delete-only), not planned_values.root_module. resource_changes is flat across modules, so a module-wrapped group is walked, and change.after_unknown is where unknown values live. Nothing reads child_modules today (policies/aws/vpc_required.rego:15), and AWS has no module refusal before Layer 3 (test_command.go:684).
- Shapes: inline `ingress` on aws_security_group and on aws_default_security_group (a fourth shape the epic misses), aws_security_group_rule with type = ingress, and aws_vpc_security_group_ingress_rule. Egress is never walked. The allowlist binds only at Layer 3 (test_command.go:684-704), so it closes no shape here. deny_state walks input.ec2.security_groups[].ip_permissions, because fakeaws folds every shape into the group (fakeaws origin/main handlers/ec2.go:1318-1354, 2891-2903).
- Public source: any CIDR in cidr_blocks, ipv6_cidr_blocks, cidr_ipv4 or cidr_ipv6 (state: ip_ranges, ipv6_ranges) that is not inside 10/8, 172.16/12, 192.168/16 or fc00::/7, so ::/0, the two halves and any public /32 all count. security_groups, self, source_security_group_id, referenced_security_group_id and user_id_group_pairs are not public. Prefix lists are refused on any port. A public rule is denied for protocol -1 or 'all', ports 0/0, or tcp or 6 covering 22 (0-65535 included).
- Unknowns come from change.after_unknown. An unknown public-source field counts as public, and unknown protocol or ports count as admitting 22. Suppose 5.100.0 collapses a whole inline set to unknown when one element has an unknown reference. Then fall back to that resource's configuration block constants, walking module_calls. A block whose ports or protocol are not constants (dynamic, attribute syntax, reference) is denied, as is one whose public-source field is not a constant. aws_vpc.main.cidr_block is known at plan when the VPC CIDR is a literal or a var default (aws-instance network.tf:2,28), so it is judged as the private CIDR it is.
- deny_state uses a helper plus `not`: a group with no ip_permissions key is denied, and [] passes. It reads the mock only (ADR-0034 section 4).
- Fixtures come from real captures: `tofu show -json` plans from hashicorp/aws 5.100.0 against a sealed fakeaws, and /mock/state from fakeaws at the CI pin 6933409 (ci.yml:98; the local ../fakeaws predates #26). The .tf variants (a local child module, and a copy of network.tf lines 19-41), capture.sh (modelled on testdata/topology/aws/capture.sh) and the trimmed JSON go under internal/harness/testdata/ingress/aws/, with trimmed copies inline in the _test.rego. Nothing goes under policies/ except .rego, because rego.Load (opa.go:58) loads data files. Any case no capture can produce is named in the review-pass file, never hand-shaped.
- Deny text is repair input that is learned verbatim, so it names the address, the rule and the fix (a literal private CIDR, only the ports the scenario needs).
- Layer 1 runs on every AWS plan (validate_command.go:66-67). LLM-run outcomes that can change: aws-instance, aws-vpc-network, aws-full-stack, aws-eks and aws-rds. Unchanged, having no security group: aws-dynamodb, aws-iam, aws-route53, aws-s3, aws-secrets-manager and aws-sqs. No training scenario names the criterion, so Layer 2 changes for none. In CI, the e2e fixture aws-web-step-one gains the criterion.
- ADR-0034 gains an AWS section. The prohibition is on openings. Four shapes are walked at any module depth, because a walk that misses one fails open on it. Unknowns fail closed, and deny_state still never reads real state.
