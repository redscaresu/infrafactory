# The AWS scope claim primitives. The claim is an SSM compare-and-swap that recognises its own retried put. Release is by value. Takeover names the holder and never overwrites. The stamp is read-only, and a no-default-VPC check completes the set

New file internal/harness/aws_scope.go. Constants: AWSScopePrefix=/infrafactory/layer3/, AWSClaimParameter and AWSStampParameter (HLD:166-174); the stamp's value is the account id. Extract newAWSSSMClient from aws_ami.go:30-45; it has the shape of newAWSEC2Client (aws_ec2_reads.go:31-45). NewAWSClaimHolder(runID) returns <runID>@<hostname>:<pid>, unique per process, validated against ^[A-Za-z0-9._+-]+@[A-Za-z0-9.-]+:[0-9]+$ because it goes into a pasteable command. The primitives are these. TakeAWSClaim(holder) sends PutParameter Overwrite=false. On ParameterAlreadyExists it GetParameters: a value equal to holder means taken (our retried put landed); any other value means ErrAWSScopeClaimed naming that value. On any other put error it resolves with a GetParameter; if that fails too, the result is ErrAWSClaimOutcomeUnknown and the caller treats the claim as held. It runs under context.WithTimeout(context.WithoutCancel(ctx)), as Scaleway's create does (run_project_lifecycle.go:46-58). ReadAWSClaimHolder returns the holder or reports it absent. ReleaseAWSClaim(holder) does a GetParameter, refuses when the value is absent or different, then DeleteParameter. DeleteParameter takes only a Name (ssm api_op_DeleteParameter.go), so the Get-then-Delete window gets a ponytail: comment naming it as the ceiling. TakeOverAWSClaim(previous, holder) is the takeover protocol, owned here: GetParameter must equal previous; a previous on this host whose pid is alive is refused; then DeleteParameter, then PutParameter Overwrite=false. If another holder took the claim in between, it refuses naming them. No code path sends Overwrite=true. AssertAWSScopeStamp(account) reads only. AssertNoAWSDefaultVPC is a paginated DescribeVpcs that checks IsDefault client-side. Also add TestAWSScopeClaimAgainstRealSSM. It is skipped unless INFRAFACTORY_AWS_LAYER3_REAL=1. Its env comes only from harness.AWSSealedEnv(~/.config/infrafactory/layer3-aws.env, $INFRAFACTORY_AWS_LAYER3_REGION), never from shell AWS_*. It runs VerifyAWSIdentity against $INFRAFACTORY_AWS_LAYER3_ACCOUNT and the stamp check before any write, registers a t.Cleanup release, and ends by asserting that DescribeParameters under the prefix returns exactly the stamp. It is named in no workflow.

**Done when:**
- Fake doer: a PutParameter whose first attempt lands and returns a 500, and whose retry answers ParameterAlreadyExists, leaves TakeAWSClaim taken, because the stored value equals holder. A stored different value refuses naming it. A failed follow-up Get returns ErrAWSClaimOutcomeUnknown.
- TakeAWSClaim called with an already-cancelled ctx still sends the PutParameter and returns taken.
- ReleaseAWSClaim with a stored different value, or with none, refuses and makes zero DeleteParameter calls.
- TakeOverAWSClaim: a stored value other than previous refuses naming it, with zero writes. A previous whose host is this host and whose pid is alive (the test's own pid) refuses. A Put that answers ParameterAlreadyExists after the Delete refuses naming the new holder. In every case the recorded request bodies contain no Overwrite=true.
- A source test fails if any non-test harness code passes AWSStampParameter to PutParameter or DeleteParameter.
- AssertAWSScopeStamp refuses a missing stamp, naming docs/operations.md § Layer 3 (AWS), and refuses a value other than the account. AssertNoAWSDefaultVPC refuses when IsDefault=true is on page 2, and treats a 403 as an error.
- NewAWSClaimHolder refuses a runID containing a space or a quote. aws_sdk_audit_test.go and aws_ami_test.go pass unmodified.
- TestAWSScopeClaimAgainstFakeaws (internal/e2e) runs these steps: take; a second holder refused naming the first; a wrong-holder release refused; release; retake; take over from the named holder; stamp absent refused, stamp 000000000000 accepted; no default VPC. The test is in ci.yml's 'AWS against fakeaws' list (ci.yml:96-109).
