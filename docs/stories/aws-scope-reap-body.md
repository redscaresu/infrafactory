# reap's AWS body verifies account, stamp and claim at the delete site, deletes in real AWS dependency order with settles, and is proven per action against fakeaws

New file internal/harness/aws_reap.go: ReapAWSScope(ctx, env, doers, endpoints, sleeper, account, principal, holder, strays). This is the AWS form of ADR-0023 rule 4 (ADR-0023:30). Before its first mutating call it runs VerifyAWSIdentity (account and principal), AssertAWSScopeStamp(account) and ReadAWSClaimHolder==holder, so a caller cannot reach the deletes without the gate. The order is real AWS dependency order. Instances are terminated, then the loop settles until they are terminated. NAT gateways are deleted, then the loop settles until they are deleted. Elastic IPs are disassociated when AssociationId is set, then released. These must precede the IGW detach, because DetachInternetGateway fails while the VPC has mapped public addresses. Launch templates follow, then images deregistered, then snapshots. Volumes are next, with a settle until available. Network interfaces are detached if attached, the loop settles until available, then they are deleted; the detach is asynchronous. Key pairs are deleted. Every non-default group's rules are revoked, then the groups are deleted. Subnets are next. Route tables are disassociated, then deleted. Internet gateways are detached, then deleted. VPCs are last. The SSM row is report-only: the key may write only the claim. A failed delete does not stop the rest. The body returns per-item errors, and the caller's sweep is the verdict. It never touches the claim. The table exports the EC2 actions it sends, for the policy test.

**Done when:**
- Fake doer: STS naming another account, a missing stamp, or a claim held by another holder each give zero mutating calls.
- Fake doer with one stray per collection, including an associated EIP, a NAT gateway, a volume, a detached ENI, an image, a snapshot and a launch template: each is deleted by the right call. DisassociateAddress is sent only when AssociationId is set. An asynchronous detach (the ENI is detaching on the first poll) is followed by DeleteNetworkInterface only once it is available.
- TestEveryAWSSweptCollectionHasAReapDelete: every table row except the single SSM row has a delete step. A precedence table holds these pairs: instances before volumes, ENIs, security groups, subnets and the IGW detach; NAT gateways before Elastic IPs, subnets and the IGW detach; Elastic IPs before the IGW detach; images before snapshots; ENIs before security groups and subnets; security groups, subnets, route tables and IGWs before VPCs. Swapping any listed pair fails it.
- TestEveryAWSAllowlistedTypeIsSweptAndReaped (internal/cli) reads config.Default() (config.go:334-342) and infrafactory.yaml (:184-192). Every aws_ entry must map to a swept collection: aws_route and aws_route_table_association map to route tables, and aws_eip to Elastic IPs. An unmapped aws_ type fails, and an empty AWS list fails.
- TestAWSReapAgainstFakeaws (internal/e2e). It plants a VPC, a subnet, an attached IGW, a route table associated with a route to the IGW, two security groups where one references the other, a key pair, an unassociated Elastic IP and an instance. A recording doer wrapping NewLoopbackOnlyHTTPClient asserts that TerminateInstances, ReleaseAddress, DeleteKeyPair, RevokeSecurityGroupIngress, DeleteSecurityGroup, DeleteSubnet, DisassociateRouteTable, DeleteRouteTable, DetachInternetGateway, DeleteInternetGateway and DeleteVpc were each sent and answered 200. It also asserts that a Describe by id of the subnet, groups and route table answers NotFound before DeleteVpc is sent, which defeats DeleteVPC's cascade (fakeaws repository/ec2.go:59-119). After that the sweep is clean. The test says fakeaws proves decoding, not order. It is in the ci.yml list.
