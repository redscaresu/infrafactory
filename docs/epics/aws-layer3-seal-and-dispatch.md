# Layer 3 is keyed on the scenario's cloud at every seam, the AWS sealed environment and in-process AWS client exist and are proven sealed, and AWS refuses the live-path entry points. No cloud, no claim, no sweep list: the seams and the seal only.

**Done when:**
- Every Layer 3 seam takes the scenario's cloud: credential preflight (internal/cli/test_command.go:1083 assertSandboxCredentials, :1098 sandboxCommandEnvForProject, :1178-1210 assertRealScalewayEndpoint), the project/claim lifecycle seam (ensureRunProject, internal/cli/run_project_lifecycle.go:25, unconditional today per :17-19), OrphanSweepRunner (internal/cli/runtime.go:84-85 takes a Scaleway secretKey; :444-446 hardwires NewScalewayOrphanSweep; call at test_command.go:1682), the failure-path sweep (internal/cli/run_command.go:782-795), cleanup after a failed apply in `test` (test_command.go:895-910), the interrupt guard (internal/cli/reap_command.go:144-178) and reap (:40-62), the sandbox destroy/placement (internal/harness/sandbox_destroy.go:171-220), and the four gate call sites (test_command.go:615, generate_command.go:743, deploy_command.go:106, live_upgrade.go:89). A `cloud: aws` run with sandbox_deploy enabled never calls the Scaleway Account API, sweep or destroy; a cloud with no Layer 3 branch fails closed before any API call; every existing Scaleway test passes untouched (contradiction 3).
- The AWS sealed environment: the strip is the prefix AWS_* appended to harness.SandboxStripEnv (internal/harness/sandbox_deploy.go:32-48; matching in internal/cli/exec_runner.go:70-96); TF_VAR_* and TF_CLI_ARGS* STAY in the strip list (they are cost guards, ADR-0023 rule 1; v1 misread the HLD here); HTTP_PROXY, HTTPS_PROXY and SSL_CERT_FILE pass through because they are not AWS_*. Set exactly AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION, AWS_EC2_METADATA_DISABLED=true, AWS_SHARED_CREDENTIALS_FILE and AWS_CONFIG_FILE to non-existent paths. A test proves an inherited AWS_ENDPOINT_URL_EC2, AWS_PROFILE and TF_VAR_volume_size reach neither tofu nor infrafactory's own calls.
- The AWS client is chosen and sealed: aws-sdk-go-v2 (go.mod has no AWS dependency today) built from the builder's map alone, with static credentials and explicit per-service endpoints, never LoadDefaultConfig, because the process strip only applies to child processes (exec_runner.go:143) and the default chain reads AWS_ENDPOINT_URL_*, ~/.aws/config `services` and IMDS. A test with a planted ~/.aws/config `services` entry and AWS_PROFILE proves the in-process client ignores both (contradiction 19).
- One builder serves tofu, preflight, the AMI resolver, the sweep and reap; it refuses without the mode-0600 credential file beside layer3.env. Preflight calls sts:GetCallerIdentity and refuses a wrong account or principal, tested against fakeaws STS (fakeaws-step-one-surfaces item 3) and with a fake doer.
- Placement for AWS: ChildScopedTypes and the placement check are per-cloud. The gate's parent check requires a scaleway_ prefix (internal/cli/layer3_hcl_shape.go:670) and unplacedResources places by project_id (sandbox_destroy.go:212-217), so an AWS state-only teardown would refuse every resource. AWS places a resource by account id from arn or owner_id, a child (aws_route, aws_route_table_association) through its parent; a shared helper answers 'does this state resource belong to account X' and aws-layer3-gate's post-apply check reuses it (contradiction 18).
- `--keep`, `deploy` and `live upgrade` refuse `cloud: aws` with a message naming the live path (today all three gate only on sandbox_deploy.enabled: internal/cli/run_keep.go:31-35, deploy_command.go:95-107, live_upgrade.go:79-91).

**Out of scope:** The claim, the sweep's collection list, reap's AWS body, hand setup, any real-cloud call (aws-layer3-claim-sweep-reap); the HCL gate rules (aws-layer3-gate); the layer-neutral provider block (aws-layer-neutral-hcl).
