# One dedicated, empty AWS member account is the Layer 3 scope; infrafactory claims it, proves it empty and cleans it on the success, failure and interrupt paths, all fail-closed (Goal 3; Rollout 1). No generated HCL yet.

**Done when:**
- Hand setup, recorded in docs/operations.md § Layer 3 (AWS) 'Scope setup': member account created clean under AWS Organizations, default VPC in the pinned region deleted, SCP denying every action outside the region and every service but EC2, SSM and STS, IAM user with aws:RequestedRegion condition, SSM prefix and stamp parameter, credential file location and mode. This epic does NOT write the IAM action list (aws-web-live-on-real-aws owns it); it records that the policy in force was sufficient for claim, sweep and reap.
- Claim lifecycle, each a test with a fake doer: the claim is PutParameter Overwrite=false under the prefix, value = run id, taken before anything touches the cloud; a second run while it exists is refused naming the holder; a clean sweep deletes the parameter and the next run takes it; a failed sweep keeps it and ends the run (Goal 5 exception: not re-entrant); reap on a scope it has proven empty releases it; an interrupt leaves it and prints `infrafactory reap <scenario>` (today the guard prints 'nothing to clean up' when there is no state and no marker, reap_command.go:171-175; for AWS the claim, and resources from a partial apply with no state written, exist in exactly that case). The stamp is a second parameter preflight and reap read; preflight asserts the default VPC is gone and states it cannot assert the SCP.
- The sweep enumerates the HLD's fixed collection list independent of the allowlist: instances unless terminated, volumes, network interfaces, Elastic IPs, security groups other than a VPC's default, VPCs, subnets, internet gateways, route tables other than a VPC's main, NAT gateways, key pairs, owned snapshots and images, launch templates, SSM parameters outside the prefix (step-two rows are aws-web-stack-load-balancer's). Per collection, a fake-doer test fails naming a planted item, one with the stray on page 2, and one where the collection answers 403. The settle loop retries while anything is shutting-down, deleting or detaching, bounded, then fails closed; incomplete pagination fails.
- A test asserts every AWS entry in allow_resource_types maps to a swept collection and every swept collection has a reap delete, in dependency order; it FAILS on an empty AWS allowlist so it cannot pass vacuously before aws-layer3-gate lands the entries (that epic's Done re-runs it).
- reap has a state-free path gated by scope id, stamp and claim. On the failure path and after a failed apply, the AWS sweep runs and the claim is kept unless the sweep proves the scope empty; every failure raised while resources may exist carries the recovery command (ADR-0023 amendments, docs/decisions/0023-...md:55-81), through the seams aws-layer3-seal-and-dispatch parameterised.
- Real-cloud proof (user-run): a planted detached network interface AND a planted unassociated Elastic IP, the two things the mock never models, each make the sweep fail naming them; `infrafactory reap` removes both; a second run during the claim is refused naming the holder; the release leaves the prefix holding only the stamp.
- New ADR: whole-scope ownership for AWS (claim, stamp, collection list, settle loop, SCP as the enforced boundary). ADR-0023 records the third implementation (rules 1-4 for AWS, naming aws-layer3-seal-and-dispatch for rules 1-2) and that ADR-0025 is not carried over. This is the only epic that edits ADR-0023's record.
